# SafeTensors Toolkit 整体设计

## 1. 架构原则

严格格式语义与平台 I/O 分离；header 解析不得静默丢失 duplicate key；分片先产生不可变计划，再由 native 执行不透明 byte-range 复制。bootstrap 的 `declare` 仅冻结契约。

## 2. Package 职责与依赖

| Package | 职责 | 主要依赖 |
|---|---|---|
| `model` | 公共快照、限制、错误、报告、计划 | 无 |
| `codec` | prefix/header 严格解析、序列化、布局验证 | model |
| `diff` | 两个有效快照的确定性结构差异 | model |
| `query` | 按选择器查询 tensor 声明与 header-only 尺寸 | codec/model |
| `shard` | tensor 粒度分片/合并计划和 index 语义 | codec/model |
| `analysis` | dtype/shape 汇总、metadata 校验、shard set 校验 | codec/model |
| `transform` | header-only tensor 重命名事务 | model |
| 根 package | 类型重导出和纯内存用例编排 | model/codec/diff/query/shard/analysis/transform |
| `native` | seek/read、bounded copy、原子输出 | codec/model/transform |
| `cmd/sftk` | 命令、渲染、退出码 | model/codec/diff/query/shard/native |

## 3. 核心数据流

```text
prefix/header bytes → strict JSON event stream → HeaderSnapshot
→ checked tensor sizes + interval validation → ValidatedFile
→ info / diff / query / rename / ShardPlan
→ native bounded range copy → temp files + digests → atomic publish
```

native 先读取小固定前缀，再按 hard limit 读取 header；data buffer 不整体进入内存。plan 中的每个 range 绑定源文件 identity（size、header digest、可选完整 digest），执行前复核。

## 4. 核心公开契约

```moonbit
pub fn parse_header(input : Bytes, limits~ : ParseLimits) -> HeaderSnapshot raise SftkError
pub fn validate_layout(header : HeaderSnapshot, data_len~ : UInt64) -> ValidatedFile raise SftkError
pub fn diff(left : ValidatedFile, right : ValidatedFile) -> DiffReport
pub fn plan_split(file : ValidatedFile, policy : ShardPolicy) -> ShardPlan raise SftkError
pub fn plan_merge(index : ShardIndex, files : ArrayView[ValidatedFile]) -> MergePlan raise SftkError
pub fn query_tensors(file : ValidatedFile, query : TensorQuery) -> TensorQueryResult raise SftkError
pub fn plan_renames(file : ValidatedFile, renames : ArrayView[TensorRename]) -> RenamePlan raise SftkError
```

`HeaderSnapshot` 保留 entry 源序，但所有公开报告按 tensor name/差异类别稳定排序；JSON 序列化器显式控制键顺序。

## 5. 严格解析与验证算法

prefix 用 `UInt64` 解码并在转为 `Int` 前检查；JSON 使用保留重复字段的 tokenizer/parser。shape 逐维 checked multiply，再乘 dtype width；offset 区间排序副本用于 O(n log n) 重叠/空洞检查，不依赖 header 声明顺序。

## 6. 分片与合并算法

按稳定 tensor 顺序贪心装箱，策略同时限制 shard bytes 和 tensor count；单 tensor 超限时默认独立成 shard并报告。每个输出先构造 canonical header 和新 offsets，再复制对应原始 ranges。index 完成且所有 shard 验证成功后才发布。

## 7. 错误与一致性模型

解析/验证错误携带 byte offset、JSON path 或 tensor name；I/O 错误携带操作和逻辑路径，不含数据。无全局状态；首版串行。原子性边界为单个输出集在同一目录的 staging→rename，跨文件系统不承诺原子。

## 8. Target 边界

纯计算 package（model/codec/diff/query/shard/analysis/transform）计划跨 wasm/wasm-gc/js/native 检查；`native` 与 `cmd/sftk` 仅 native。官方 Python 库只在 interop 脚本作为外部 oracle。

## 9. ADR

| ADR | 决策 | 未选方案 | 理由 |
|---|---|---|---|
| ADR-001 | 严格 duplicate-key JSON parser | 通用 map parser | 普通 map 会丢失安全相关信息 |
| ADR-002 | 不透明 range copy | 解码再编码 tensor | 内存与性能可控，不改变数值 |
| ADR-003 | tensor 粒度分片 | tensor 内切片 | 保持格式/索引简单可互操作 |
| ADR-004 | 计划与执行分离 | 边算边写 | 可 dry-run、可复核、易测试 |
| ADR-005 | index schema 版本化 | 猜测所有生态变体 | 输出可复现，失败清晰 |
